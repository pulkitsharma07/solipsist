The agents are [Pi](https://github.com/earendil-works/pi), an open-source coding agent ([more about Pi here](/docs/engines/pi/)). It's built into Solipsist, so
there's nothing extra to install. Pi needs an AI model, and there are a few ways to give it one.

## Paste an OpenRouter key

The first time a page opens with no AI model that can run, Solipsist asks for an OpenRouter key:

<Shot name="connect-model" title="Connect an AI model" alt="The Connect an AI model dialog: where to get an OpenRouter key, and a box to paste it" />

1. Sign in at [openrouter.ai](https://openrouter.ai) and add a little credit.
2. Open [Keys](https://openrouter.ai/settings/keys) and create one.
3. Paste it into the dialog and choose **Save key**.

Solipsist checks the key with OpenRouter, then keeps it on your computer, in your system's keychain (the macOS
Keychain, Windows Credential Manager, or the Secret Service on Linux). Where there's no keychain, it goes in
`~/.config/solipsist/openrouter.key`, which only you can read. The key is sent to OpenRouter and nowhere else.
`pi.key_store` and `pi.key_file` in the [configuration](/docs/reference/configuration/) change where it's kept.

If you choose **Not now**, the status bar's [Connect an AI model](/docs/reference/status-bar/#model) brings the dialog back.
To remove a saved key, run `solipsist forget-key`.

## An OpenRouter key in your environment

Set the key in your environment, in your shell's profile (`~/.zshrc`, `~/.bashrc`) to keep it. A key set this way comes
before one saved in the dialog:

```bash
export SOLIPSIST_OPENROUTER_KEY=sk-or-...
```

Solipsist doesn't read a `.env` from the folder it runs in: that folder may be someone else's.

More on [OpenRouter](/docs/start/openrouter/). You can also put it in `solipsist.yaml` as `pi.openrouter_key`, but that file is easy to commit by accident. The
server never prints a key. Errors and `--print-config` only say whether one is set.

## A login you saved in Pi

If you already use Pi in a terminal, Solipsist picks up Pi's own configuration, the same way the `pi` command does in
that folder (`~/.pi/agent`, plus a project `.pi`). Your saved logins, skills and connected tools work here too. To add
a login, run `pi` and then `/login`.

## A model on your own computer

Pi can also run through Ollama, LM Studio, llama.cpp or vLLM. See [Local models](/docs/start/local-models/).

## Choosing the model

Each page has its own model. You pick it in the [agent panel](/docs/reference/agent-panel/), next to the
switch that turns the page's agents on and off, and the [status bar](/docs/reference/status-bar/#model) shows which model
the page is using. The picker shows a shortlist first, and you can search
every model Pi can run. To pin your favourites to the top of the list on every page:

```yaml
agent:
  preferred_models:
    - pi:openrouter/~deepseek/deepseek-flash-latest
```

If a run is in progress when you change the model, it finishes on the old one. If no model can run yet, the status
bar's model reads [Connect an AI model](/docs/reference/status-bar/#model) instead.

:::caution
Like Pi in a terminal, an agent can run commands on your computer, and Solipsist doesn't sandbox them. Pi's own
`write` and `edit` tools can only write to the images folder, but its shell can do anything you can.
:::
