    Copy page React component

    WhereJust above the page, on its right

    Copies the page as you see your own text (unsaved edits included), in two formats at once: markdown for GitHub and rich text for Google Docs. Markers, suggestions, margin comments and hand-written HTML comments are left out; a range's text stays.

    Use it for

    • Paste the page into a GitHub issue, PR or comment: the markdown keeps image paths as written (relative to the page's folder), which render when that folder is in the repo.
    • Paste it into Google Docs: headings, lists, tables, code and links come across, and the images are embedded (SVG and other formats drawn as PNG), up to 8 MB of images in all; past that the rest are links to this server.

    When touched

    • Click: copies. Its label is always "Copy page as markdown".
    • Copied (green check) for two seconds; its title says if any image was linked rather than embedded, and why.
    • Couldn't copy (red) when the browser refused the clipboard; its title has the reason.
    • No key: ⌥⌘C is the card's chat, and ⇧⌘C is the browser's inspector.

    Prompts (settings dialog) React component

    WhereThe settings dialog, first tab

    Every instruction the agents are given, to read and change: the protocol, the prompt each run is sent, one prompt per kind of placeholder, and the chat prompts.

    Use it for

    • Change how the agents behave without editing the app: shorter answers, another voice, a house style for one kind of placeholder.
    • See what the agents are actually told, with the slots the server fills in.

    When touched

    • A prompt in the list: opens it in the editor. "edited" marks a prompt whose file of yours is in use; "unsaved", one with a change not yet saved.
    • Save: keeps the text as a file in your prompts folder (~/.config/solipsist/prompts). It is refused, with the reason, if it is empty or leaves out a required {slot}.
    • Revert: drops the unsaved changes.
    • Reset to default: deletes your file and brings the built-in text back.
    • A change applies to the next run and the next agent started; one already running or waiting keeps what it began with.
    • Closing with unsaved changes asks once.

    Page review React component

    WhereStatus bar or agent panel (the button); the left margin and the sheet (the questions)

    A reviewer reads the page and leaves questions beside the passages it can't follow. It writes nothing in the page: a question is a note, not a change.

    Use it for

    • Press Page review to have the page read like a reader would: what is unclear, unsupported or missing.
    • See where each question is about: the passage is underlined, and its card sits in the left margin.
    • Open a question to read it in full, take it down (Dismiss) or carry it into the chat (Ask).

    When touched

    • Page review blinks and reads “Reviewing…” while it runs; its steps are in the agent panel, and when it ends the panel says what became of every question.
    • A highlighted passage or its card opens the question. With room, the popover hangs in the margin beside the passage; on a laptop it opens just under it. A thin line joins it to the passage and the rest of the page steps back.
    • The status bar counts the questions, which matters when the window is too narrow for the margin.
    • Escape, a click away or ✕ closes it. Questions are stored in the page's hidden block and never change the text.
